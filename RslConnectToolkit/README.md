# RslConnectToolkit - Current Usage Guide

## Purpose
RslConnectToolkit provides two operational flows:

1. `Check` flow: run environment checks and generate a text report.
2. `Setup` flow: guide SPN/delegation setup for a target Nasuni share.

Primary source scripts:

- `Check.ps1`
- `Setup.ps1`
- `Build.ps1`

Bundled distribution output:

- `Release/RslConnectToolkit.ps1`
- `Config.json`

## Current Project Structure
- `Check.ps1`: Main check runner.
- `Setup.ps1`: Setup wizard (SPN + prerequisites + delegation).
- `Build.ps1`: Bundles source into `Release/RslConnectToolkit.ps1`.
- `Config.json`: Default full-check config.
- `ConfigDev.json`: Dev/light config.
- `Modules/`: Check modules (`RslCheck-*.psm1`).
- `Reports/`: Reports generated by source `Check.ps1` runs.
- `Release/Reports/`: Reports generated by bundled release script.

## Prerequisites
1. Windows.
2. PowerShell 5.1+.
3. For `-RunAsSystem` and setup changes: elevated PowerShell (Run as Administrator).
4. For AD operations in setup flow: rights to modify SPN/delegation where required.

## Running Checks (Source Script)
Run from repository root.

Default config (`Config.json`):

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\Check.ps1
```

Use development config (`ConfigDev.json`):

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\Check.ps1 -Config ConfigDev
```

Run as SYSTEM (creates temporary scheduled task):

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\Check.ps1 -RunAsSystem
```

With verbose output:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\Check.ps1 -Verbose
```

## Running Setup (Source Script)
`Setup.ps1` requires `-NasuniShare`.

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\Setup.ps1 -NasuniShare NAS-01
```

Optional setup parameter:

- `-PrimaryAgent <ComputerName>` (default: local computer name)

What setup does:
1. Shows SPNs to add and optionally applies them with `setspn -S`.
2. Installs AD PowerShell prerequisites if missing.
3. Configures constrained delegation (`Set-ADComputer -PrincipalsAllowedToDelegateToAccount`) after confirmation.

## Build and Bundle
Build bundled script:

```powershell
./Build.ps1
```

Build parameters:

- `-BuildType Dev|Release` (default: `Dev`)
- `-Signup` (optional signing step)

Examples:

```powershell
./Build.ps1
./Build.ps1 -Signup
./Build.ps1 -BuildType Release -Signup
```

Build output:

- `Release/RslConnectToolkit.ps1`
- `Release/Config.json`
- `Release/ConfigDev.json`

Signing notes:

- `Dev`: creates a self-signed code-signing certificate.
- `Release`: expects a trusted certificate by thumbprint configured in `Build.ps1`.

## Running the Bundled Script
From `Release` folder:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\RslConnectToolkit.ps1 -Action Check -Config Config
powershell.exe -ExecutionPolicy Bypass -File .\RslConnectToolkit.ps1 -Action Setup -NasuniShare NAS-01
powershell.exe -ExecutionPolicy Bypass -File .\RslConnectToolkit.ps1 -Action Setup -NasuniShare NAS-01 -PrimaryAgent primary-agent
```

Bundled script parameters:

- `-Action Check|Setup` (default: `Check`)
- `-Config <NameWithoutJsonExtension>` (default: `Config`)
- `-NasuniShare <ShareName>` (required for `Setup`)
- `-PrimaryAgent <ComputerName>` (optional for `Setup`, default: local computer name)

## Configuration
`Check.ps1` expects config name without `.json` extension and resolves it as `<ScriptRoot>/<ConfigName>.json`.

Example (`Config.json`):

```json
{
  "Checks": {
    "System": true,
    "Network": true,
    "AD": true,
    "Kerberos": true,
    "Application": true,
    "Users": true,
    "SPN": true,
    "Services": true
  },
  "Domain": "rsldev.local",
  "Ports": [53, 88, 389, 445, 636, 3268],
  "SPNs": ["rslmc/rsldev.local", "rsl/rsldev.local"],
  "Users": ["svc_app", "svc_sql", "gmsa_app$"]
}
```

## Report Output
Report naming format:

- `Report_yyyyMMdd_HHmmss.txt`

Report sections:
1. `=== Settings ===`
2. `=== Checks ===`
3. `=== Summary ===`

Each row includes:

- `Check`
- `Status` (`PASS`, `FAIL`, `WARNING`, `INFO`)
- `Detail`

## Current Check Implementation Status
As of this repository state:

- `System` module has concrete checks for memory, disk, and CPU via CIM.
- `Network`, `AD`, `Kerberos`, `Application`, `Users`, `SPN`, `Services` are currently scaffold checks and return placeholder PASS details based on config domain.

## Troubleshooting
1. Config file not found
- Use config name without extension (for example `-Config ConfigDev`).
- Ensure `<name>.json` exists beside the running script.

2. Module not found
- Check `Modules/RslCheck-<Name>.psm1` exists for each enabled entry in `Checks`.

3. Function not found in module
- Each module must export `Invoke-RslCheck<Name>` (for example `Invoke-RslCheckAD`).

4. SYSTEM run fails
- Run elevated PowerShell.
- Ensure Task Scheduler service is available.
- Review `LastTaskResult` reported by the task.

5. Setup AD command failures
- Confirm RSAT AD tools are installed.
- Confirm account permissions for SPN/delegation changes.

## Recommended Workflow
1. Start with `ConfigDev.json` while validating script execution.
2. Switch to `Config.json` for full run.
3. Use `-RunAsSystem` only when required by environment policy.
4. Build release bundle after validating source scripts.
